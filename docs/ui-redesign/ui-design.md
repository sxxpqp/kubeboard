# KubeBoard UI 设计

版本：2.0 · 2026-10-22 · 替代此前全部 UI 方案

前置：[产品需求](requirements.md)、[产品对标](product-comparison.md)。以下为目标设计，不能当作当前代码已实现清单。

## 页面框架

56px 顶栏、216px 范围导航、24px 内容边距。顶栏显示品牌、集群身份、刷新与账号；导航先选择集群/项目范围，再显示对应菜单。单集群不显示假的集群切换器。范围切换到对应概览，已有项目不能隐式更换。

列表页：面包屑 → 标题与说明/创建 → 类型页签 → 搜索/状态筛选/刷新 → 表格 → 计数与分页。项目内不重复项目选择器和项目列。

详情页：返回/面包屑 → 左侧 280px 对象摘要与操作 → 右侧内容页签。主内容默认资源状态，摘要不与首屏重复。元数据、环境变量和事件各有位置。全部对象统一独立页面，不再使用简略详情弹窗。

## 资源页面内容及布局

| 页面 | 首屏与区块顺序 | 专属交互 |
|---|---|---|
| 集群/项目概览 | 身份与更新时间 → 健康/异常 → 资源用量或不可用说明 → 警告事件 | 异常带筛选进入列表；项目概览包含配额 |
| 工作负载列表 | 类型页签 → 名称/状态/镜像/副本/时间 | 创建、更多；DaemonSet 使用节点计数 |
| 工作负载详情 | 顶部独立操作栏；运行时左侧版本 → 中间 Pod → 最右侧倒序生命周期 | 版本配置对比、回退；日志/终端合并；运行时不放副本调整和镜像更新 |
| Pod 详情 | 容器实时状态与原因 → 资源/端口/探针 → 卷 → 调度四项检查 | 所属控制器/节点；逐容器日志与终端 |
| Job/CronJob | 执行状态或调度表达式 → 任务/Pod → 容器模板 → 条件 | 任务与运行实例的上下文区别明确 |
| Service/Ingress | 端口与地址/按主机的路由 → 选择器/后端 → TLS 引用 | 后端服务或 Pod 直达 |
| PVC/PV | 请求与实际容量/卷容量 → 绑定关系 → 使用者/回收策略 | PV、PVC、存储类、Pod 直达 |
| StorageClass | provisioner → 绑定与回收 → 扩容 → 参数 | 关联卷资源 |
| ConfigMap/Secret | 类型与键数 → 键值表 | 长值展开，Secret 固定遮蔽，不自动解码 |
| ServiceAccount | 自动挂载规则 → 镜像拉取凭据 → 引用 | 凭据直达且不暴露值 |
| HPA/NetworkPolicy | 目标及副本范围/策略作用范围 → 指标/规则 → 条件 | 用语义表格呈现规则，不打印整份 spec |
| Node/Namespace | 系统与容量/项目汇总 → 条件/配额 → 关联资源 | 调度封锁、项目资源入口 |
| Event | 时间、类型、对象、原因、来源、消息、次数 | 对象直达；工作负载/Pod 范围明确 |

## 编辑、日志与状态反馈

创建流程按产品需求提供类型适配，确认页显示将创建的对象。编辑要保留未修改和未知字段。删除、重启、回退必须标识项目、名称和影响；提交期间防重入。

日志浮层最大 90vw，持续显示项目/Pod/容器；实时跟随与自动滚动分开。切换或关闭取消旧流，显示连接状态；复制/下载注明当前已加载范围。终端关闭时解释原因。

首次加载骨架；刷新保留内容；错误可重试；空资源与空筛选有不同引导。状态同时用颜色、图标和文字。长文本在内容区域换行/横向滚动，不能撑破页面。

## 适配与验证

1440×900 为主画布；1280 减少留白；1024 摘要改顶部、导航可收起。对正文对比度、键盘焦点、长名称、错误态、空态分别验收。

UI 对比见 ui-comparison.md。官方文字资料只能证明内容与流程，不能证明像素一致；截图对照、交互原型和真实集群验收未完成前不得标为视觉通过。

## 工作负载操作栏与命令字段（2026-10-22）

工作负载标题下方使用独立、可换行操作栏：编辑 / 预览与编辑 YAML / 调整镜像 / 伸缩 / 日志与终端 / 复制 / 重启 / 删除。运行时内容区域不重复这些操作。DaemonSet 隐藏伸缩。镜像修改只作用于选定容器，不调用旧的“替换所有容器镜像”行为。复制先生成新名称和独立选择器的清单，用户确认后创建。

编辑进入表单，预览与编辑 YAML 直接进入 YAML。尚未表单化的类型退回完整 YAML，不能假装字段已全部覆盖。启动 command 与 args 在容器配置中分别展示；数组项内的空格、引号和反斜线必须往返保留，不能通过 join/split 空格损坏命令。复杂未覆盖字段仍由完整 YAML 编辑，不承诺表单已覆盖 Kubernetes 全部 Schema。

## 最新输入布局修订（2026-10-23）

创建和编辑共用五步独立页面：基本信息 → Pod 设置 → 存储挂载 → 高级设置 → 确认。Pod 设置中的“端口与命令”将 command 和 args 各放在一个独占整行的单行输入框，避免并排或多行数组输入。空格分隔数组项，项内空格使用引号；既有参数格式化后可逆，不改变实际数组。引号或转义不完整时显示错误并阻止切换/提交。此修订替代之前按数组项换行的方案。

实装状态与验证边界见 [实施记录](implementation-status.md)。
