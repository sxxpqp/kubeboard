# 第二轮：UI 设计与 KubeSphere 对比

日期：2026-10-22 · 比较对象为 ui-design.md v2.0 目标方案

## 比较方法与证据限制

沿用 product-comparison.md 的 S1/S2。当前没有同版本 KubeSphere 控制台的完整截图样本；本轮能比较信息架构与文字描述支持的交互，不能把颜色、宽度、密度、页签顺序或布局推断写成视觉复刻通过。

## 逐项比较及回写

| 维度 | 当前证据/参照 | v2.0 UI 方案 | 差距与处理 |
|---|---|---|---|
| 管理范围 | S1 的项目与资源分类 | 集群/项目范围切换，项目独立概览 | 路径方案自主拟定；后续核对实际切换流程 |
| 列表结构 | 官方资源管理任务需要类型区分 | 类型页签、搜索/筛选、资源表、分页 | 具体密度与按钮位置待截图校准 |
| 详情上下文 | S2 有属性与资源状态内容 | 常驻属性区、独立内容页签 | 信息分层有依据；左右分栏宽度为拟定值 |
| 容器诊断 | S2 的 Pod/容器访问链路 | Pod 展开后逐容器操作 | 不再默认先选容器再找副本；具体图标待校准 |
| 元数据与环境变量 | 产品明确独立内容任务 | 单独页签，引用来源可读 | 具体页签顺序待同版本对照 |
| 存储详情 | 产品对比未完成官方逐字段核验 | 绑定/容量/使用者分区，PV/PVC 分开 | 保留待核实状态，不能声称已经完全一致 |
| 网络与配置 | S1 分类有依据，详情证据有限 | 端口/路由/键值/凭据引用分别设计 | 交互布局待各类截图对照 |
| Job / CronJob / HPA / 策略 | 产品矩阵明确不同语义 | 执行/调度/指标/方向等专属区块 | 不使用整份 spec 代替 UI；官方详情待核实 |
| 创建与编辑 | 产品定义输入与确认任务 | 工作负载向导，简单资源单页 | 原型尚未交互验证；未知字段保真必须测试 |
| 日志/终端 | 核心诊断链路已确认 | 上下文常驻，状态可见，流与滚动分开 | 窗口尺寸和控件编排为本项目设计 |
| 视觉系统 | 暂无同版本截图证据 | 中性画布、层次与绿色状态体系 | 色值/留白/字体/圆角全部待视觉校准 |
| 可用性 | 项目自身验收要求 | 键盘、长文本、空/失败态、1024 适配 | 需要原型和真实页面检查 |

## 第二轮回写结果

已写回 UI v2.0：取消旧简略详情弹窗；摘要与首屏不重复；工作负载按 Pod 展开；存储类型分开；网络策略采用语义表格；Secret 不自动展示值；范围与筛选不混淆；错误和未知不冒充空状态。

## 尚未满足的视觉验收门槛

1. 获取同一版本的集群概览、项目列表、工作负载列表/详情、Pod、存储、网络、配置及任务页面的官方截图或可访问演示。
2. 逐页对照框架、内容密度、表头、属性区、操作位置、弹窗和空状态，记录差异并更新设计。
3. 生成关键页面高保真原型，验证范围切换、列表进入详情、容器日志及返回路径。
4. 原型通过后再继续业务代码；实现后用真实集群截图验收。

当前结论：完成文档层面的 UI 比较和修订；高保真原型与像素/交互对照尚未通过。之前的构建和测试只能证明当时代码可构建，不能替代此门槛。
