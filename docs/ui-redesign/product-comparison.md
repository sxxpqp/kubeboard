# 第一轮：产品设计与 KubeSphere 对比

日期：2026-10-22 · 比较对象为 requirements.md v2.0 目标方案，不是代码完成度

## 证据与判定规则

[S1：KubeSphere 3.4 项目用户指南](https://www.kubesphere.io/docs/v3.4/project-user-guide/)用于验证产品分类与范围。
[S2：4.2 工作负载详情](https://docs.kubesphere.co/v4.2.0/07-cluster-management/05-application-workloads/01-workloads/03-view-workload-details/)仅用于补充详情流程，不冒充 3.4 的 UI。

已核实表示有官方文字依据；设计取舍表示本项目主动选择；待核实不能当成对齐通过。功能相似不等于内容、操作和视觉均相同。

## 逐项比较及修订

| 项目 | 参照与证据范围 | 原方案问题 | v2.0 修订 | 判定 |
|---|---|---|---|---|
| 资源分类 | S1 包含工作负载、网络、卷与配置管理 | 只描述视觉骨架 | 全资源矩阵明确内容和关联 | 分类已核实 |
| 项目上下文 | S1 的项目使用场景 | 项目选择退化为列表筛选 | 集群/项目独立范围和项目概览 | 范围一致，路径为自主设计 |
| 工作负载详情 | S2 提供资源状态与对象属性等任务入口 | 通用信息占首屏 | 类型属性摘要、运行状态与容器入口 | 内容方向已核实；版本差异保留 |
| 工作负载与 Pod | S2 包含 Pod/容器访问链路 | 依靠列表弹窗 | 独立对象详情与逐容器诊断 | 核心链路已核实 |
| 发布历史 | 产品目标要求配置比较 | 只有历史列表/回退 | 加入双版本配置对比与失败反馈 | 目标明确；具体 3.4 行为待核实 |
| Job / CronJob | S1 分为不同任务类型 | 共享部署语义易误导 | 执行与定时调度模型分开 | 分类已核实，详情字段待逐页核实 |
| Service / Ingress | S1 分别列出服务和路由 | 关联入口弱 | 端口/后端与主机/路由规则分别设计 | 分类已核实，具体交互待核实 |
| PVC / PV / 存储类 | 原 3.2 存储链接本轮无法读取 | PV/PVC 混用且需求不完整 | 独立容量、绑定、使用者与回收属性 | 需求已修；官方逐项对比待核实 |
| ConfigMap / Secret / SA | S1 有配置字典、密钥与服务账号分类 | 都按通用数据展示 | 类型、数据与引用分开 | 分类已核实，细节待核实 |
| HPA / 网络策略 | S1 含 HPA，网络策略为独立能力 | 仅列名称 | 目标/指标与策略范围/方向分别呈现 | 部分核实；规则交互待核实 |
| 节点 / 项目 / 事件 | 非本轮 S1 的详情证据范围 | 旧实现反推设计 | 明确系统/配额/事件字段与关联任务 | 待官方逐页核实 |
| 监控 | S1 有完整监控相关能力 | 可能暗示能力等价 | 即时指标可用才展示，历史监控明确裁剪 | 主动裁剪 |
| 企业空间/租户/应用商店 | S1 产品范围包含更广平台能力 | 是否跟随不明确 | 不引入当前产品范围 | 主动裁剪 |

## 第一轮修订结论

已将发现的问题合并进入产品需求 v2.0：范围改为全资源内容重构；增加独立项目概览；区分执行实例和控制器；PV/PVC 分开；发布对比列为目标功能；真实错误与能力缺失分别反馈。

产品分类及工作负载主要链路可进入 UI 方案设计。表中待核实项仍是对标缺口，不能宣布“与 KubeSphere 全面对齐”；实施这些部分前需补对应官方详情证据。后续 UI 对比必须继承这些未决项。
